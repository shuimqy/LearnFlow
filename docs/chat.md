# 课程问答

从课程详情或知识库点击“课程问答”。每门课保存自己的对话，支持追问、新建、删除、刷新后恢复历史和失败重试。
回答支持 Markdown、KaTeX、知识点引用及 PDF 物理页码链接，补充解释单独展示。
问答页使用紧凑页头，回答区占满剩余屏幕高度，消息单独滚动；输入框保持可见并随内容增高。
手机端通过“历史对话”按需展开会话列表，阅读时保留完整宽度。
桌面端可分别收起主导航与对话历史，收起状态会保存在本机浏览器，顶部按钮可随时展开。
问答区不限制最大宽度，两栏收起后铺满可用屏幕。

## 图片消息

主对话与分支都可以点击输入框旁的图片按钮、粘贴截图或把图片拖入输入区。
支持 JPG、PNG、WebP，每条最多 4 张、每张最多 5 MB；可只发图片，也可补充文字问题。
发送前可预览、移除图片；已发送图片可点击放大，刷新后仍可查看。
网络失败且服务端尚未保存时保留输入和图片；问题已保存时，通过同一请求 UUID 重试即可，无需重新上传。

账号 LLM 必须启用图片识别且模型实际支持视觉输入。设置未启用时，前端提示并禁用图片发送，后端也会检查；
纯文字消息继续可用。模型服务实际不支持图片时会保留失败消息和图片，修正账号设置后可重试。

新图先经过 `observe_images` 节点：视觉模型记录题干、公式、图表标签与不确定之处，然后进入意图分流。
`image` 路径可直接读图、解释图表或根据完整题目条件推导，标注“根据图片分析”，不伪造知识库引用。
要求结合课程资料、核实知识或缺少课程依据时，仍进入现有 RAG；最终生成同时读取图片和检索依据，
避免只依赖文字识别丢失公式或图示关系。只有实际检索时才可能调用 Embedding，图片本身不会直接入库或建立向量。

文字追问可沿用本会话最近一条含图用户消息的图片和已识别内容；模型不支持视觉时只使用已保存的文字背景。
从图片回答创建分支时，快照保存分叉时对应的图片 ID 与元数据，后续主对话新图不会进入已有分支；
分支也可上传自己的图片，后续优先使用自己的最近图片。分支的“提问背景”中可查看源图片。

图片在服务端进行实际解码，拒绝损坏文件、动图和超过 2000 万像素的图片；校正 EXIF 方向，清理元数据，
最长边缩至 2560 像素，保存处理后的 PNG 或 JPEG。因此提供查看的是发送给模型的处理版本。
`chat_images` 用 PostgreSQL BYTEA 保存有限大小的图片，图片内容延迟加载；消息列表只返回元数据。
图片与消息在同一事务内创建，通过外键级联清理，避免预上传失败留下无主附件。
`GET /api/chat/images/{image_id}` 每次检查课程所属账号，按 no-store 返回，不能凭图片 ID 读取其他账号资料。
删除分支只删除该分支自己的图片；源图片仍属于主对话。删除主对话或课程时，关联图片与 checkpoint 一起清理。
LangGraph 只保存识别文本与状态，图片二进制和 base64 不进入 checkpoint。

## 回答流程

使用 LangGraph `StateGraph` 编排问答，FastAPI 负责账号归属、请求幂等与并发控制。
明确询问上一条问题仍可走本地 `recall`；其余请求先由 `plan` 使用账号 LLM 判断意图，再选择回答路径。
主对话与分支使用同一套分流逻辑，记录在各自 LangGraph checkpoint 中。
模型按账号统一解析：未自定义时沿用系统默认；更换 Embedding 时，所有课程使用旧配置直到新索引就绪。
配置和切换规则见 [账号设置](account-settings.md)。

1. 验证课程和对话属于当前用户，保存问题与 `generating` 状态的回答。
2. 判断本轮需要普通交流、回顾历史、沿用已有知识依据、重新检索，还是先澄清问题。
3. 必要时将指代改写为独立问题，检索当前课程；已有依据足够时，重新校验其归属和版本后复用。
4. 将相应上下文交给账号配置的 LLM（默认 `qwen3.8-flash`），允许模型在发现依据不足时转去补查。
5. 校验结构化回答和引用编号，再检查知识版本，将回答与引用快照一起保存。

检索为空时直接说明依据不足，不再调用回答生成；有检索结果但与问题无关时，由模型说明缺少什么。
模型只能引用服务端提供的编号，不能自行生成知识点或 PDF 链接。
引用编号的校验不代表事实准确率评估，公式和推导仍需结合原始资料检查。

“我上个问题是什么”等明确回顾请求直接读取本会话的前一条用户提问，不调用 LLM 或 Embedding，
返回 `retrieval_mode=conversation`，不附课程引用。分支没有自己的前文时使用创建快照中的原问题，
随后仅回顾分支自身消息。其他措辞的回顾和总结由模型结合有限历史回答；同时提供第一条问题和上一条问题，
超出提供范围的历史不能编造。复述历史表示“此前讨论过”，不表示历史知识结论已被重新核实。

## 按需检索

| 分流 | 典型需求 | 是否生成查询向量 |
| --- | --- | --- |
| `chat` | 问候、致谢、学习情绪、交流偏好 | 否 |
| `history` | 回顾、总结、重排已有聊天 | 否 |
| `context` | 对当前定义换种说法、翻译、解释已有推导 | 已有有效依据足够时不生成 |
| `retrieve` | 新概念、新题目、扩展例题、核实纠错、查课件 | 索引就绪时查询向量接口；可命中缓存 |
| `clarify` | “这个怎么算”但缺少可定位的题目或上下文 | 否，先问清条件 |
| `image` | 图片理解、图表说明、条件完整的截图题目 | 否，实际需要课程资料时再转检索 |

`chat_intent.py` 使用结构化 `ChatPlan`，结合用户当前需求、有限历史和可用知识候选作语义判断。
planner 输入的历史最多 8000 字符、每条最多 2000；最多六个知识候选，每个只提供前 800 字符。
这是意图和上下文判断，不生成 Embedding；除本地上一条问题回顾外，通常会增加一次短 LLM 调用。
最终消息的 Token 用量累计本轮成功的分流、上下文回答和最终生成调用，不只统计最后一次生成。

已有依据来自本会话最近四条已完成助手消息，以及分支创建时保存的源引用。
复用时按当前账号、课程、有效状态、chunk ID 和知识版本重新读取正文和来源，不能把历史助手回答当成证据。
旧分支缺少引用快照时，仅在源回答内容哈希匹配时读取其引用，不读取分叉后新增的主对话消息。
分流期间知识被改动，改走检索；回答生成期间被改动，仍按原版本保护拒绝保存并允许重试。

普通交流或回顾若发现实际需要新知识，可返回 `needs_retrieval`；复用依据回答时返回该状态或 insufficient，
都会进入课程检索。补查最多一次，不把中间的补查请求保存成可见回答，也不会无限循环调用模型。
模型不能在课程生成路径中自行声明 conversation 来绕过引用；对话路径也不能生成伪造知识引用。
分流失败或格式不符合约定时保守地检索，并明确提示本次补查；不会用缺少依据的回答冒充成功。

页面显示实际处理阶段，包括“正在读取图片”；直接聊天标注“根据对话上下文”，复用依据标注“沿用对话中的课程依据”，
需要澄清时标注“需要补充问题信息”。分流依赖模型判断，仍需结合实际课程持续评估，不保证每次最优。

## 查询向量缓存

同一后端进程中，相同最终检索文本的查询向量缓存五分钟，最多 256 条。缓存只保存文本哈希和向量，
不保存问题明文、原始 API Key 或检索结果；每轮仍重新查询当前知识块。
按用户、课程、Embedding 完整配置指纹和凭据摘要隔离。更换模型、维度、服务地址、版本或 Key 都不会混用。
失败不缓存；删除课程清理对应缓存，删除期间尚未返回的旧请求也不能重新填入。服务重启清空，各进程独立缓存。
并发的相同查询首次到达时仍可能各自调用一次。缓存不代表接口权限恢复，权限错误仍按关键词降级规则处理。

## LangGraph 状态与恢复

主对话和每个分支各有一个稳定的 `user:{uid}:course:{cid}:chat:{conversation_id}` thread_id。
使用官方 `langgraph-checkpoint-postgres` 的同步 PostgresSaver，checkpoint 与业务数据在同一本机
PostgreSQL 中。页面显示准备、检索、生成、引用校验、保存等实际执行阶段；当前仍为非流式回答。

运行上下文中的数据库连接、账号 API Key 不写入 checkpoint，仅保存本轮问题、有限历史、检索依据与回答状态。
显式关闭 LangSmith tracing，不向外部追踪服务提交对话。模型调用仍遵循账号配置，向所配置服务发送必要的文本。
checkpoint 的节点错误使用通用提示，避免保存模型服务错误正文。

`chat_graph_threads` 关联会话与本次运行标识；写 checkpoint 时锁定并核对标识，阻止已删除或失效请求写回。
删除主对话会级联删除分支、消息、上下文快照，以及所有关联的 checkpoints、blobs、writes；删除分支只清理该分支。
清理针对当前数据库，数据库备份和已有日志按各自保留策略处理。正常会话的 checkpoint 当前不做定期裁剪。

失败重试复用请求 UUID，重新分流并核对所需知识的当前版本，不直接重放旧 checkpoint 中的证据。
服务重启后历史与图状态保留，未完成的请求在原五分钟处理租约到期后可重试，不会自动续跑模型调用。
图状态保存成功与最终回答提交不属于同一事务；若回答已提交、最后一次 checkpoint 写入失败，仍返回已保存的回答。

## 分支提问

主对话每条已完成的回答下方都有“分支提问”。选中正文或补充解释中的不超过 6000 字符的片段，
也可使用浮出的“针对选中内容提问”。Markdown / 公式以消息 ID 和选中文本定位，暂不保存字符偏移。
分支在右侧抽屉打开，手机上占满屏幕；可连续追问、查看引用、返回主对话，再从原回答下重新打开。
URL 的 `?branch=` 支持刷新后恢复。当前只支持主对话创建一级分支。

创建时可选择：

| 范围 | 继承内容 |
| --- | --- |
| `focused`（默认） | 片段、原问题、当前回答与补充解释，最多四条前文 |
| `full` | 片段、原问题、当前回答与补充解释，最多二十条前文 |
| `minimal` | 仅片段和原问题；整条回答入口取其前 6000 字符作为片段 |

完整来源回答和补充解释另存于创建时的快照；提供给模型的继承历史最多约 32000 字符。
前文每条最多 2000 字符，focused 前文预算 4000，full 为 10000；过长内容按字符截取并标记，尚未做结构化摘要或 Token 精确预算。
分支自身最近十条消息仍受原 10000 字符预算约束。主对话分叉点之后的消息不会进入已有快照。
历史引用编号会移除。分支同样按需复用已验证的知识依据或检索当前课程，历史回答不作为本轮有效依据。

创建分支先保存问题及 pending 回答；打开抽屉后用同一请求 UUID 生成首个回答。
若连接中断，可以重新生成或重试；已完成回答不会重复调用模型。关闭抽屉不会删除分支。
可从原回答下删除分支，生成期间返回 409；删除主对话同时清理关联分支，迟到的生成不能重建已删除记录。
当前尚未实现分支总结合并、保存知识笔记、应用纠错、分支结束状态和知识点卡片直接创建分支。

## 检索范围与排序

所有候选都限制为当前用户、当前课程、有效状态和当前知识版本。
检索使用知识正文，原始课件引用作为来源元数据保留，避免已纠正的结论再次被旧原文覆盖。

`qwen3.7-text-embedding` 将问题转换为 1024 维向量，pgvector 按余弦距离取前 24 块。
语义候选默认要求相似度至少 0.45；同时补查英文词、中文词与连续双字关键词，并取前 24 块。
两路以倒数排名融合（`1 / (30 + rank)`），最多返回 6 块，同一知识点最多 2 块。

索引未就绪或向量接口失败时可以使用关键词检索，回答下方会显示实际降级提示。
索引已完成仅表示保存了知识向量，不代表查询问题时 Embedding 接口仍可调用。
接口返回 `403 / AccessDenied.Unpurchased` 时提示开通该模型或在账号设置更换有权限的配置，
既有向量不会被删除，当前回答退回关键词检索；不自动混用不同模型的向量。
关键词补查当前扫描课程有效文本，向量查询尚未建立 ANN 索引；课程规模增大后需调整。
知识库页面的搜索仍是文本包含匹配，与问答的混合检索分别实现。

## 后台向量索引

新增、自动提取、修订和恢复知识时，同一事务先保存正文、修订和新检索块；提交成功后才入队。
每批最多 20 个知识点，使用现有 Redis `documents` 队列，由 Windows RQ SpawnWorker 执行。
启动入口仍是 `start.bat`，不需要新增服务。

新块从 `pending` 开始；成功写回后为 `ready`，记录模型、维度与时间。
失败为 `failed`，记录通用提示及一分钟重试间隔。页面可提交重试，提问时也会补交待处理索引。
账号更换模型或维度时，新旧索引分别保存，查询问题始终使用与当前索引对应的模型；
新索引全部就绪后统一切换，旧向量不会混入新模型检索。补建只处理需要更新的知识。
归档立即清理检索块；旧版本任务不能覆盖新版本。

数据库事务和 Redis 入队并非原子操作。Redis 不可用时知识仍保存成功，块保持待处理；
后续提问、页面“更新知识索引”或命令行可补交，不静默生成模拟向量。

从仓库根目录查询或补建一门课，替换 `<课程ID>`：

```powershell
uv run --all-packages python -m app.cli.knowledge_index status --course-id <课程ID>
uv run --all-packages python -m app.cli.knowledge_index enqueue-course --course-id <课程ID>
```

`enqueue-course` 需要 Redis 与 Worker；`index-course` 可在当前进程直接批量执行。
补建会将该课程当前知识文本发送到本机配置的 Embedding 服务，并产生模型调用费用。

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `EMBEDDING_AUTO_INDEX` | `true` | 事务提交后及提问时自动补交索引；关闭后仍可手动提交 |
| `RAG_MIN_SIMILARITY` | `0.45` | 语义候选的最低余弦相似度，尚未针对真实课程校准 |
| `CHAT_MAX_TOKENS` | `4096` | 每次问答的模型输出上限 |

## 会话、引用和失败处理

`conversations` 保存课程归属、标题与处理标识，`chat_messages` 保存顺序、请求 UUID、内容、
状态、引用快照、检索方式、模型与 Token 用量。删除对话级联删除消息；删除课程同时清理对话。

模型历史最多取最近 10 条已完成消息，每条最多 2000 字符，总计最多 10000 字符。
历史包含正文与补充解释，只帮助理解追问；知识依据每轮重新校验或检索，不直接继承旧引用编号。
同一对话一次只生成一个回答，同一请求 UUID 重试不会重复创建问题或已完成回答。
失败时保留问题，并提供重试；进程中断后超过五分钟，可在读取或重试时恢复为失败状态。
模型鉴权、权限、额度、超时、输出格式和引用校验失败使用服务端固定提示；日志记录内部错误类别和请求标识，
不记录问题正文、模型返回正文、API Key 或异常原文。

回答生成期间所用知识被修订或归档，会拒绝写入该回答并提示重试。
已完成回答保留当时的知识版本和文本；再次读取时标记已更新、已归档或原文件已删除，
不把历史引用悄悄替换成新正文。PDF 链接始终经过当前用户的文件权限校验。

## 接口

所有路径位于 `/api` 下，并要求登录。

| 路径 | 功能 |
| --- | --- |
| `GET /courses/{id}/retrieval/status` | 当前课程的知识块及模型配置状态 |
| `POST /courses/{id}/retrieval/index` | 补交待处理索引 |
| `GET/POST /courses/{id}/conversations` | 列出或创建对话 |
| `GET /courses/{id}/conversations/{cid}` | 读取主对话或分支元数据 |
| `GET/POST /courses/{id}/conversations/{cid}/branches` | 列出或创建一级分支，创建接受源回答 ID、片段、问题和上下文范围 |
| `DELETE /courses/{id}/conversations/{cid}` | 删除对话，生成期间返回 409 |
| `GET /courses/{id}/conversations/{cid}/messages` | 默认最近 100 条，可用 `before` 向前分页 |
| `POST /courses/{id}/conversations/{cid}/messages` | 提问或使用相同 `request_id` 重试 |
| `POST /courses/{id}/conversations/{cid}/messages/with-images` | multipart，`request_id`、可选 `content` 和 1–4 个 `files` |
| `GET /chat/images/{image_id}` | 当前账号的消息图片，要求登录 |
